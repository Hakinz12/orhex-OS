# ORHEX OS — Architecture Specification

## Overview

ORHEX OS is a memory-powered personal operating system built for the **Tatum x Walrus Total Recall 2026** hackathon (*Smart Agents for Real Life* track).

Context fragmentation is the primary limiting factor of conventional LLM chat interfaces: every conversation begins with a blank slate, requiring users to repeatedly restate goals, constraints, preferences, and personal context. ORHEX OS bridges this gap by persisting a verified, portable memory graph using **Walrus Memory Mainnet**, gathering live contextual blockchain data via **Tatum Sui RPC**, and formulating proactive recommendations with **Google Gemini**.

---

## Architectural Principles

1. **Decoupled Provider Adapters:**
   Every external dependency (LLM, Memory Provider, Blockchain RPC, Database) is abstracted behind standard Python interfaces. Swapping an LLM provider or updating an RPC endpoint requires zero changes to core domain logic.

2. **Truthful Asynchronous Persistence:**
   A durable local `PENDING` operation is committed before the Walrus write.
   Operations become `CONFIRMED` only after a blob ID is confirmed, `FAILED`
   for definite failures, or `RECONCILIATION_REQUIRED` when the outcome is
   uncertain. Uncertain writes are not blindly retried.

3. **Backend-Confined Security:**
   The frontend browser client never receives Walrus delegate private keys,
   Tatum secret keys, or database connection strings. Memory endpoints require
   an opaque bearer token mapped to a provisioned application user. Only a
   verified database principal determines memory ownership or namespace.

4. **Explainable Anticipation:**
   Proactive interventions (deadlines, goal stagnations, transaction notifications) are generated by a deterministic rule engine before synthesis. Every recommendation includes explicit citations linking back to the origin memory ID or on-chain transaction digest.

## Module Directory Map

- `services/api/app/adapters/`:
  - `llm/`: `BaseLLM` interface and `GeminiAdapter`.
  - `walrus/`: `BaseWalrusMemory` interface and `MemWalAdapter` with Ed25519 request signature generation.
  - `tatum/`: `BaseBlockchain` interface and `TatumSuiAdapter` with JSON-RPC 2.0 communication.
- `services/api/app/core/`:
  - `config.py`: Environment validation via `pydantic-settings`.
  - `database.py`: SQLAlchemy async engine and session factory.
- `services/api/app/models/`:
  - `domain.py`: SQLAlchemy database models (Users, revocable access tokens, Goals, Commitments, MemorySyncRecords).
  - `schemas.py`: Pydantic input/output validation schemas.
- `services/api/app/services/`:
  - `orchestrator.py`: Core conversation flow and memory integration.
  - `anticipation_engine.py`: Proactive rule triggers.
